# 表达矩阵研究工作台：设计与原型

**状态：** 2026-10-22 用户已接受`chat-workspace.html`聊天主界面原型及知识库入口方案，并授权指挥其他聊天开始工作。范围从表达矩阵开始，支持上传或搜索研究提供的矩阵，暂不做FASTQ比对/定量。设计获准不代表正式功能已经实现。

## 1. 用户目标与本轮边界

零基础研究者从一份表达矩阵或一个研究问题开始，完成来源选择、数据类型检查、样本分组、分析方案确认、执行、绘图与结果解释。用户无需先按程序格式制作 metadata CSV，仍需确认实验条件、比较方向和科学方法。已有专业 counts+metadata 入口保留为高级选项。

本轮唯一编号任务46只交付设计与交互原型，不修改API/统计/前端生产代码，不访问真实模型、下载真实研究数据或运行统计。原先试作的FASTQ模块及测试已在用户纠正范围后撤回；其合成数据检查不计为表达矩阵功能验收。任务45的未提交文献改动与renv原改动保留。

## 2. 两种数据入口

### 上传表达矩阵

CSV/TSV单文件 → 预览维度/表头/基因ID与样本 → 确认方向、ID列与样本列 → 明确数据类型和处理历史 → 编辑/确认分组。分组信息不足时收集用户输入，不从列名猜测实验设计后直接执行。格式识别可以提出建议，但用户能查看并修正。

### 搜索公开研究

自然语言目标/关键词或明确GSE → 受控GEO候选 → 展示组织/物种/研究设计、可用矩阵、矩阵类型和原始出处 → 用户选中 → 展示下载大小并确认 → 下载校验 → 同一矩阵检查与样本确认。只有原始测序文件的研究显示“没有可直接分析的矩阵”，本阶段不转入FASTQ。候选文字和文件名都不是数据类型证明，未知类型保持待确认。

## 3. 数据类型决定可用方法

- Raw counts：保留既有双组DESeq2链路；整数外观只证明数值兼容，不证明未归一化，必须保留来源依据或用户确认。
- TPM/FPKM/已归一化或log表达：不能取整送入DESeq2。原型展示独立方法确认/探索分析分支；正式差异方法需要后续独立设计、统计基准和审批，不因原型出现而视为已实现。
- 芯片/未知类型：要求确认平台与处理历史，明确兼容性；不得自动套用RNA-seq统计。
- 基因ID映射、低表达过滤、样本排除、阈值、富集与解释均需可见的处理记录；不自动加入原MVP尚不支持的协变量/配对设计。

## 4. 信息架构：以聊天为主，按需预览文件

用户审阅后明确要求采用类似Codex的单一聊天布局，撤回最初两种工作台方案的推荐。左侧管理项目及项目下的聊天；中间是当前对话，底部是支持文件附件的消息输入框。平时只聊天，不常驻步骤导航、结果工作区或独立AI助手栏。

右侧文件预览默认收起。点击消息里的文件或右上角文件入口后打开，可查看矩阵、图表、报告和文本，切换已打开文件；关闭后恢复完整聊天空间。右侧是文件阅读区域，不承载另一套分析流程。普通方法提问无需创建分析任务。

知识库管理入口放左侧底部，可创建/改名/删除库、导入PDF、查看解析/索引状态，完成后返回聊天。输入框旁选择本对话使用的库，复用现有按对话保存的范围。普通聊天附件与明确加入长期知识库分别操作：矩阵不自动入文献索引，PDF附件也不静默长期入库。

## 5. 关键交互

1. 从现有聊天提问或新建聊天；左侧切换项目与聊天。草稿和附件属于各自聊天，输入框通过加号添加文件，Enter发送、Shift+Enter换行。
2. 上传矩阵、查找公开研究均从对话发起。候选研究、数据类型检查和需补充的信息直接出现在消息中；点击附件可预览，不要求先提交metadata CSV。
3. 样本信息与分组作为对话中的可确认内容，正式实现需能修改样本纳入、条件和比较方向，至少每组2个样本。当前原型只展示示例分组确认，不冒称实现完整校验。
4. 对话内呈现数据类型、方法、比较、阈值和预期图表，保留明确批准/拒绝。科学参数变化撤销旧审批，执行器继续独立校验revision/hash；聊天式界面不等于自动批准。
5. 运行状态、停止、失败说明和结果文件链接都在对话中。图表与报告点击后在右侧阅读，AI解释链接实际结果或论文证据，不伪造统计数字。原型运行仅为本地模拟；真实上传文件只预览和确认收到，不生成虚构分析结果。
6. 窄屏以聊天为主，项目列表通过抽屉打开；文件预览打开时临时占据主区，关闭回到聊天。聊天与文件始终可相互返回。

## 6. 实现拆分（原型审阅后才形成编号实施计划）

- 表达矩阵预览/类型契约、分组表单、metadata自动生成，与既有Dataset及审批串联。
- GEO现有搜索/下载/映射的统一入口，真实小型公开矩阵来源与分组验证。
- 规范化矩阵的探索分析与适用差异方法，各自独立统计验收。
- 项目/聊天侧栏、对话及附件输入框、对话内审批/运行消息、可开关文件预览，复用已有React/API/SSE与产物服务。
- 从本地矩阵及公开矩阵分别跑通真实示例，再与固定脚本/通用Agent比较完成率、结果、人工干预、耗时。

不重写已工作的R统计、审批与manifest，不扩大到single-cell/long-read/多Agent，不安装服务器工具。界面原型不承诺上述后续能力已实现。

## 7. 原型验收

当前原型为`chat-workspace.html`，取代此前`expression-workbench.html`的两种方案。默认只显示项目与聊天；文件可从消息/文件列表打开并关闭；草稿切换、附件发送、新建项目/聊天、表格/文本和图表/报告阅读有效；示例分组及审批留在对话中，未勾选确认不能批准，停止模拟后不生成结果。桌面、深色与390/320px窄屏可用且无页面级横向溢出。所有示例明确标识，不联网检索或执行真实统计。

原型不验证生产矩阵识别、分组约束、GEO下载或科学方法。第2–3节为后续实现约束，不能以界面演示替代统计或来源验收。
