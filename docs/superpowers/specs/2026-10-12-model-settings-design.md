# Bio-Agent 模型设置与统一调用设计

**状态：** 用户于 2026-10-12 批准对话中方案，并授权新建任务开发，开发模型指定 GPT-6.1。

**基线：** `agent/bio-agent-mvp` / `24374c9`，沿用 `.worktrees/bio-agent-mvp`。本规格属于任务 37；保留 bulk RNA-seq 双组 DESeq2、单 Agent、确定性统计计算和人工审批。

## 1. 目标与现状

正常使用者在“设置 → 模型与 API”完成连接配置，保存多个模型后在聊天输入区切换，无需编辑 `.env` 或重启服务。环境配置只作为可选兼容入口。

现有 `ModelProfileStore`、系统凭据库、模型配置 CRUD 和聊天选择器均已实现，应复用。当前模型表单常驻结果侧栏，“设置”仅展开 Skills/MCP；编辑配置和本轮模型共用 `selectedProfileId`，容易相互影响。分析图在启动时通过环境 Settings 构造 Planner，而工作台只把模型快照作为审计上下文传入，不能保证分析规划使用聊天所选模型。这两处都是本任务的必要修改。

## 2. 界面与交互

设置提供统一入口及“模型与 API / Skills / MCP”页签，模型管理不再常驻结果侧栏。离开设置回到聊天时保留当前对话、消息、结果和工作状态。采用与现有布局一致的独立设置视图或可关闭面板，桌面和窄屏均可操作。

模型管理区展示保存的配置，支持新增、编辑、删除和测试连接。字段包括显示名称、接口协议、API Base URL、API Key 和模型 ID；协议以用户可理解的名称展示，并提供填写提示。

首版协议为 OpenAI 兼容 Chat Completions、DeepSeek、Ollama，复用现有 `openai_compatible / deepseek / ollama` 标识。DeepSeek 使用已有兼容设置；Ollama 不要求 API Key。Anthropic Messages 和 OpenAI Responses 不在本次范围，不把这些协议误标为已经支持。

模型管理的编辑选择与聊天的模型选择使用独立状态。查看或编辑一个配置不得悄悄切换聊天模型。支持对话记忆选择；新增配置成功后可选用它，无配置时提供明确的设置入口。

保存和更新后无需重启。提交中禁用重复操作，失败时给出可操作提示，不把未成功保存的 Key 当作已配置；API 不回显 Key。探针只发固定、非敏感请求，明确报告实际验证的能力，不把结构化输出成功等同于全部工具调用能力已验证。

## 3. 聊天与分析统一模型

每次发送时固定所选 profile ID 与不含密钥的配置 revision/snapshot。切换模型只影响下一轮；既有请求、待审批计划和统计 attempt 保留原快照。

聊天、分析规划及必要的规划修正使用该轮同一配置。不得在聊天 profile 失败时回退到环境 Planner，或把 profile 快照仅写入审计字段而仍调用环境模型。

使用受信任的服务端依赖传递和现有适配器装配 Planner；凭据仅在请求边界解析，模型客户端、Key、闭包或其他不可序列化对象不进入 LangGraph state/checkpoint、run index、event 或 manifest。新增的服务端 profile 绑定必须同时覆盖上传分析和 GEO 导入后创建计划的入口。

旧 API 的无 profile 调用保留既有兼容语义；无环境 Key 时，不得使工作台内已配置且有效的模型无法聊天、规划或审批。明确区分旧 API 的默认模型依赖与工作台按轮次的依赖，不通过放宽 readiness 隐藏真实不可用状态。

profile 的 revision/snapshot 约束不得被替换为实时读取可编辑参数。凭据替换沿用请求边界规则；配置已删除、协议不支持或凭据缺失时明确失败，不伪造连接成功、不隐式换模型。

## 4. 存储与安全

复用现有 SQLite profile/对话存储和操作系统凭据库。只保存配置、非密钥快照和凭据引用；禁止把 Key 写入浏览器 localStorage、数据库明文字段、URL、日志、checkpoint、manifest、测试产物或 Git。

环境 profile 在设置中标为可选只读兼容配置，不作为新用户的必填路径。已有 profile、对话、run 和旧 manifest 可继续读取，不重建用户数据库，不覆盖 `.env` 和运行数据。

不新增任意代码执行、自动下载权限、统计方法、自动审批、RAG 实现或多 Agent 产品能力。

## 5. 验收

1. 不设置模型环境 Key，仅通过页面保存一个 Mock 协议配置，即可发送消息并生成待审批分析计划。
2. 两个可区分的 Mock 模型验证聊天和 Planner 均使用当前轮模型；另一轮切换后使用另一个模型，正在执行的轮次保持原配置。
3. 上传和 GEO 来源规划均遵守同一绑定；审批前 R 调用仍为零。
4. 编辑模型设置不改变聊天选择；刷新和切换对话恢复各自选择；删除当前配置显示明确恢复入口。
5. 配置保存、Key 保存或连接测试失败时不展示成功，接口响应和持久化状态不含测试密钥。
6. 运行相关后端/前端回归、typecheck、build、Ruff、mypy、仓库规定 hooks 和暂存差异检查；对受影响行为补少量有意义的红灯用例，不堆叠实现镜像测试。
7. 浏览器固定 fixture 覆盖设置入口、保存配置、返回聊天、切换模型与生成待审批计划。真实模型测试继续 Mock，不读取用户 Key，不调用真实账户。
