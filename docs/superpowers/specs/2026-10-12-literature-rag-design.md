# 本地文献知识库与 API 设计

日期：2026-10-12。状态：用户已批准，按任务 38→39→40 分别开新聊天顺序实施；批准不代表知识库已经实现。

## 目标与使用方式

用户从本地批量导入含正文、图片和表格的 PDF。Bio-Agent 在本机解析、保存和索引文献，聊天中选择知识库后可以基于文献回答；其他本机程序也可以直接调用检索和问答 API。问答复用任务 37 的模型配置和当轮配置快照，不要求环境 API Key。

这是一项独立于 bulk RNA-seq 统计执行的知识能力。文献不能提供执行指令、充当 counts，或代替人工批准分析计划。

## 选型与替代方案

推荐 Docling 本地解析组件，接入现有 FastAPI/React；本地 embedding 与关键词混合检索，小规模向量持久化优先验证 Qdrant local。解析器、embedding 和检索存储通过独立接口封装。依赖作为可选知识库功能安装，未安装时现有聊天和分析仍可启动，并返回明确的知识库未就绪状态。

MinerU 是解析器备选：仅当代表性文献验证表明有必要时替换或增加，不默认同时安装两套大型解析依赖。RAGFlow 是整套独立服务备选，但当前已有工作台、API 和模型配置，首次接入优先减少额外服务。来源与许可证核验记录在 `docs/research/2026-10-12-literature-rag-options.md`。

具体依赖和本地 embedding 的模型版本、权重许可证、下载体积、CPU/内存要求由任务 38 的兼容性实验记录并锁定；不宣称未经实验的语料质量。缺失权重时提示安装步骤，不在收到问答请求时静默下载。

## 模块一：本地导入与结构化解析（任务 38）

- 知识库和文献使用服务端生成的 ID。浏览器多文件选择上传，不接受任意服务器文件路径；首版不增加自动扫描目录。
- 原始 PDF、解析结果、图表资源、任务状态、版本和哈希保存在配置的本地知识库目录，运行数据不进入 Git。
- 持久化状态为 QUEUED、PARSING、PARSED、INDEXING、READY、FAILED、CANCELLED。任务 38 的解析完成态为 PARSED，不宣称已可检索；任务 39 索引完成后才能发布 READY。后台解析与 Web 请求隔离，提供阶段进度、取消和重试；进程重启后明确标记中断任务，可由用户重新开始。
- 相同库内以原始文件哈希去重。重新索引创建新 revision，完整发布后才可检索；失败或取消的半成品不能成为有效证据。删除先从可检索集合移除，再清理资源。
- 正文、表格、图片和图注保留章节、PDF 页索引（1-based）、位置、元素 ID、原始哈希和解析器版本。表格保留表头、单位、脚注和跨页分段；无法识别时显示质量提示。
- 图片保存裁剪资源及图注、可用 OCR。首版默认不做视觉语义推断；图片相关回答标明只依据图注/OCR。未来视觉接口需显式选择支持图像的模型，生成描述记录为派生内容，不能充当论文原文或精确数值。
- 使用受控子进程、资源和超时限制解析不可信文档；不执行嵌入脚本、附件或文献中的命令。

验收：真实本地解析经过授权的数字、扫描、双栏、含图表和跨页表格样本；逐项检查文字顺序、页码、表头/单位/脚注、图注和资源定位，记录用时与资源要求。允许明确记录解析缺陷，不允许假解析替代实际验收。

## 模块二：检索、引用与对外 API（任务 39）

- 依据章节和元素边界分块，表格、图片图注单独形成可检索单元，保留父段落与相邻上下文。关键词检索和本地向量检索融合，中文问题与英文文献使用具备多语言能力的本地 embedding。
- 索引记录 embedding 模型版本和维度。模型变更必须重新构建索引；不同版本不得混查。Qdrant local 由单后端进程持有；迁移服务端模式另行验收。
- 扩展现有 KnowledgeRetriever，保持旧 HTTPS evidence 契约兼容，为本地来源增加明确的带版本引用类型。引用包括库、文献、revision、chunk、元素、页码和内容哈希，通过 ID 获取资源，不向客户端暴露任意本地路径。
- `POST /api/v1/knowledge/search` 接受 query、knowledge_base_ids、top_k，返回命中原文、页码、章节、内容类型和资产引用；不调用问答模型。
- `POST /api/v1/knowledge/ask` 接受 question、knowledge_base_ids、model_profile_id，建立问答任务并返回任务/事件入口；支持流式状态和回答。只有 READY 文献参与检索；只将必要命中片段发送至指定模型。
- 无命中时返回 NO_EVIDENCE，不编造答案。证据与模型提示分隔；文献中的指令不能成为系统指令。服务端验证答案引用的 ID、revision 和 hash 属于本轮实际检索集合。该校验保证来源归属，不能代替人工判断答案是否正确解释原文。
- 提供知识库 CRUD、文献上传/列表/状态/删除、任务取消、PDF/图表资源接口，均采用受控 ID。API 路径、请求响应 schema、错误码和示例在实施计划与 OpenAPI 中固定。
- 外部本机脚本可使用 API。复用本地 Host/Origin 与 CSRF 边界，并将 knowledge 路径纳入保护；示例演示获取本地会话 token 后调用，不通过放开 CORS 或绕过 CSRF 实现易用性。跨机部署和多用户鉴权另行设计。

验收：真实 embedding 和持久化向量检索、关键词融合、重启后仍可检索、跨库隔离、删除/重建 revision 后旧证据不可用；Mock 问答模型验证流式失败处理、选定 profile、空证据和伪造引用。给出可直接运行的本机 curl/Python 示例。

## 模块三：工作台知识库与聊天集成（任务 40）

- 工作台增加知识库管理入口：创建库、批量导入、查看阶段和失败原因、重试/取消/删除文献。
- 每个对话记录选中的知识库。当轮开始时冻结库范围、文献 revision 和模型配置，不因另一个页面的编辑而变化。
- 聊天接入受约束知识检索工具，并显示检索开始、完成、证据数量与回答流；这些是可观察的操作状态，不伪造模型内部思考过程。
- 回答展示可点击的文献、页码与原文片段；可打开 PDF 对应页、表格和图片裁剪。无法视觉理解或 OCR 质量不足时明确提示。
- 没有选库时保持现有聊天行为，知识库不影响 GEO 搜索与 DESeq2 审批。

验收：一个完整流程涵盖导入真实 PDF、等待 READY、选库提问、流式回答、打开引用、切换对话保持选择、删除后不可再次引用。组件与端到端测试以关键用户路径为主，不添加映射实现细节的重复测试。
